Decision 28. The database is 42.5 MB larger than the 2026-08-19 measurement and
`game_event` carries 49,294 dead tuples. E2026 at the measured rate projects to

## 4. What was found and fixed this session, so nobody re-finds it

**Two silent security reverts**, both measured rather than argued, both now
guarded permanently:

1. **`CREATE OR REPLACE VIEW` resets a view's options.** Measured in a
   rolled-back transaction: `['security_invoker=true']` became `NULL` after an
   option-less replace. Migration 0014 as originally written would have reverted
   migration 0011's hardening for `v_game` with no error.
   Guard: `tests/test_view_security_invoker_guard.py`, proven to fail on the
   defect by removing the clause and watching it go red.

2. **Dropping and recreating a view re-applies Supabase's default privileges**,
   granting `anon` and `authenticated` ALL privileges on the new view. Measured:
   `v_shot_data` came back with fourteen grants it did not have before the drop.
   A rebuild that only restored the captured grants would have re-exposed all six
   views. Guard: `scripts/repair_v_game_officials.py` revokes them the way 0011
   does and refuses to commit unless grants match the capture exactly.

**A view cannot be narrowed.** `CREATE OR REPLACE VIEW` widens and never narrows,
and five views depend on `v_game`. Goal 026's acceptance criterion asked for a
gate that structurally could not pass. `v_game` was repaired back to its 20-column
shape and the officiating crew now lives in `v_game_officials`, a narrow view
with no dependents whose down migration is one line and whose gate cycles cleanly.

**The legacy v1 API returns HTTP 200 for endpoints that do not exist** — a
975-byte "Not found" page, nine probed URLs sharing one checksum. Goal 024 fixed
the fetch layer.

**The v2 API is rate-limited by Cloudflare** (429, error 1015) and the limit is
undocumented. Goal 025 added backoff. The real threshold was not measured; do
not encode a requests-per-second budget as if it were known.

**Fly had two machines running**, not one, at $2.02 each — double the owner's
stated ceiling — and that also silently doubled the in-memory per-subject rate
cap. Scaled to one. `min_machines_running` is a floor, not a ceiling; machine
count lives in `fly scale`, not in `fly.toml`.
